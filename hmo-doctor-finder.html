HMO Doctor Finder

A full-stack healthcare discovery demo that helps users find doctors by HMO provider, specialty, location, patient type, rating, experience and teleconsult availability, with a demo appointment-request workflow.

Problem

Patients often need to confirm both doctor suitability and HMO acceptance before requesting an appointment. Provider discovery can become fragmented across insurer directories, clinic pages and manual inquiries.

Solution

The demo centralizes HMO, specialty, location, patient-type and consultation filters into one workflow, then presents matching doctors and supports a simulated appointment request.

Engineering

The backend is built with FastAPI and exposes provider metadata, doctor search, doctor detail and appointment endpoints. The frontend consumes the REST API directly and includes responsive filtering, doctor cards and booking interactions.

Deployment

The frontend is deployed as a Render static site and the API as a Render Python web service. Python 3.13 is pinned for compatibility with the project dependency set.

Current Scope

All doctor names, schedules, HMO relationships, ratings and clinic data are fictional demo data. Appointment requests are stored in memory and are intended only for portfolio demonstration.

Production Roadmap

Next steps include PostgreSQL persistence, real provider-directory integrations, HMO eligibility verification, authentication and RBAC, audit logs, maps, notifications and AI natural-language doctor search.
