THE CHALLENGE

Reducing friction in routine patient-record retrieval.

Problem

Healthcare staff often move across multiple screens and record sections to locate routine patient information such as allergies, medications, diagnoses, laboratory results and upcoming appointments.

Design Goal

Create a natural conversational interface without allowing the AI layer to become the clinical source of truth. Identity checks, authorization concepts and data retrieval remain explicit application responsibilities.

THE SOLUTION

Voice-to-record workflow with verification and auditability.

Voice / Text Request→Intent Detection→Patient Match→DOB Verification→Clinical Retrieval→Spoken Response→Audit Event

Conversational Retrieval

Users can request patient summaries, allergies, medications, diagnoses, latest laboratory results and appointment information using voice or text.

Verification

After resolving a patient, MediVoice requires a date-of-birth challenge before releasing the requested synthetic clinical information.

FHIR-Oriented Modeling

The prototype exposes Patient, AllergyIntolerance, MedicationRequest, Condition, Observation and Appointment-style resources to demonstrate healthcare interoperability concepts.

Auditability

Requests capture user, role, method, action, patient, resource and result metadata so access decisions remain observable during development and testing.

Backend

FastAPI handles patient search, retrieval, conversational intent processing, verification, FHIR-style bundles and audit endpoints.

Frontend

A clinician-facing browser interface supports voice recognition, text queries, spoken responses, verified patient display and recent audit events.

Testing

Automated API tests cover the core retrieval and conversational flow, including successful responses and validation behavior.

Deployment

The repository includes Docker configuration and a Render Blueprint for a single public web service that serves both the UI and API.

CURRENT STATUS

Phase 0.2 — Conversational Voice Intelligence MVP.

The current version demonstrates the complete synthetic-data retrieval loop. Planned work includes persistent storage, production-grade authentication, stronger authorization, expiring verification sessions, deeper FHIR persistence and a pluggable LLM/tool-calling layer.

Portfolio / demonstration scope: MediVoice AI currently uses synthetic patient data only and is not intended for clinical use. Production deployment with real patient information would require formal privacy, security, compliance and clinical governance controls.
