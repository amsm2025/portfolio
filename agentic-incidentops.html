Agentic
IncidentOps

An AI-assisted Site Reliability Engineering incident-management platform demonstrating evidence-driven investigation, LangGraph orchestration, deterministic policy enforcement, human-governed remediation, one-time authorization, replay protection, recovery verification and auditable operations.

GitHub Repository ↗Back to Selected Work

Problem

AI can accelerate incident diagnosis, but production remediation cannot safely depend on unconstrained model output. Operational systems need evidence, deterministic controls, explicit authorization and a durable audit trail.

Solution

Agentic IncidentOps separates AI reasoning from execution authority. Specialized agents collect operational evidence, an OpenAI-assisted RCA agent produces an evidence-grounded assessment, and a deterministic policy engine decides whether the proposed action is allowed, blocked or requires human approval.

Governance

Disruptive actions use human-in-the-loop approval and short-lived one-time authorization bound to the requested action and target service. Consumed tokens cannot be replayed; rejected replay attempts are persisted as audit events.

Recovery

After remediation, recovery verification checks service health, latency, HTTP error rate, database utilization and expected deployment version before the incident can be treated as recovered.

ARCHITECTURE

Governed agentic incident lifecycle

Incident Simulator ↓ Evidence Collection ├─ Metrics Agent ├─ Log Agent ├─ Deployment Agent └─ Database Agent ↓ LangGraph Investigation Workflow ↓ OpenAI Root Cause Agent ↓ Action Classifier ↓ Deterministic Policy Engine ↓ Human Approval (when required) ↓ One-Time Action/Service-Bound Authorization ↓ Governed Remediation Executor ↓ Recovery Verification ↓ Audit Trail + Postmortem

Validated incident scenario

The database-connection-exhaustion simulation drove checkout-api to a critical degraded state with 4.8s P95 latency, 17.4% HTTP 5xx errors and 97% database connection utilization. The investigation correlated metrics, logs, database evidence and deployment state.

Validated control path

The project demonstrated approval creation, human approval, authorization consumption, remediation execution, successful recovery and explicit rejection of a second execution attempt using the already-consumed token.

Auditability

PostgreSQL records lifecycle events including APPROVAL_CREATED, APPROVAL_APPROVED, AUTHORIZATION_CONSUMED_FOR_EXECUTION, REMEDIATION_STARTED, REMEDIATION_COMPLETED and AUTHORIZATION_REPLAY_REJECTED.

Portfolio scope

The operational environment and remediation actions are synthetic. The project is designed to demonstrate secure agentic engineering and SRE governance patterns rather than operate directly against a production environment.
